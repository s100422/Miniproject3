# 보유 배당주 진단 기능 — 실행 로드맵

보유 종목의 재무·배당이력·뉴스를 모아 **배당이 끊길 위험**과 **자랄 여력**을 판정하고,
비중을 늘릴지 줄일지 대안 종목은 뭔지 근거와 함께 제시하는 기능.

설계 근거 전문(3개 안 비교, 점수 모델, 아키텍처 도해):
<https://claude.ai/code/artifact/6755a931-4f33-4e48-a870-e8632393828e>
스키마·외부 API·함정은 [DATABASE.md](DATABASE.md).

## 채택한 구조 — 사전계산 2층 파이프라인

**분석 대상은 사용자가 아니라 종목이다.** 카탈로그 86종목의 분석 결과는 전 사용자가
공유하고, 사용자마다 다른 건 "그중 뭘 갖고 있나"뿐 — 그건 코드로 조합한다.

따라서 **AI는 야간 배치에서만 돌고 사용자 요청 경로엔 없다.** 비용이 사용자 수와
무관하게 하루 172회로 고정되고 화면은 즉시 뜬다.

원칙 하나만 지키면 된다 — **숫자는 전부 코드가 계산하고, AI는 그 숫자를 인용해
문장만 쓴다.** 인용이 실제 값과 안 맞으면 문장을 버리고 점수는 남긴다.
`gemini.ts`의 `citesRealData`·`validateCandidate`가 이미 쓰는 패턴을 확장한 것.

## Phase 0 — 전제 검증 ✅ 완료 (2026-08-15)

야후 `quoteSummary`로 재무제표 항목에 접근되는지 확인.
**결론: 쿠키+크럼을 붙이면 접근된다.** 검증 결과와 필드 경로는
[DATABASE.md의 quoteSummary 절](DATABASE.md#quotesummary--아직-안-쓰지만-접근-가능-2026-08-15-확인).

Phase 1 설계를 바꾸는 발견 3가지:

- **FCF는 `financialData.freeCashflow`를 쓰면 안 된다.** MSFT가 16.5B로 나오는데 실제는 70B대다.
  `cashflowStatementHistory`에서 영업현금흐름 − capex로 직접 계산할 것.
- **REIT 배당성향은 버려야 한다.** 순이익 기준이라 `O`가 236%로 나오고, FFO/AFFO는
  `quoteSummary`에 없다. 섹터별로 숨기거나 다른 지표로 대체.
- **캐시를 먼저 넣어야 한다.** 86종목 요청이 기존 `chart` 호출 위에 얹히는데
  캐시도 레이트리밋도 없는 상태라 429 위험이 크다.

## Phase 1 — 결정론 점수 (2~3일) ← 다음 할 일

**AI를 한 줄도 쓰지 않는다.** 코드만으로 4축 점수를 낸다.

- `ticker_analysis` 테이블 (PK `(ticker, as_of)` — 덮어쓰지 않고 쌓아서 점수 이력을 남긴다)
- `vercel.json` 크론 → `/api/analysis/refresh`, `CRON_SECRET` 헤더 검사
- **서비스롤 키 신규 발급 필요** — 지금 `src/lib/supabase.ts`는 anon이라 RLS에 막힌다
- 86종목 순회에 **동시성 상한** (기존 `Promise.all` 전량 병렬은 차단 위험)
- 4축 점수: 배당안전성 40% / 배당성장성 25% / 기업체력 20% / 밸류에이션 15%
- 섹터별 배당성향 임계값 (배당성향 70%는 리츠엔 정상, 기술주엔 경보)
- **배당함정 탐지** — 배당수익률이 자기 5년 평균 +1.5σ ∧ 12개월 주가 −20% ∧ 배당성향 경고선 초과.
  필요한 데이터는 `dividendRates.ts`가 이미 받는 8년치 응답 안에 다 있다
- **배당 성장 감속** — `1년 CAGR − 5년 CAGR`. 삭감은 감속 다음에 온다
- UI: 보유 현황 탭에 안전성 배지, `/stocks`에 점수 컬럼

> **이 시점의 제품:** "내 종목 중 뭐가 위험한지" 한눈에 보인다.
> 부산물로 기존 86건 동시 호출 문제가 사라진다. 여기서 멈춰도 쓸 만하다.

## Phase 2 — 뉴스 계층 (1~2일)

기존 `riskScreen.ts`의 이벤트 종류를 배당컷/인상에서 실적 서프라이즈·가이던스·
신용등급·소송·규제·인수합병까지 넓힌다. **출처 URL 필수 원칙과 fail-open은 그대로.**
결과는 `ticker_analysis.news`에 저장.

> **이 시점의 제품:** 숫자로 안 잡히는 악재가 배지 옆에 근거 링크와 함께 붙는다.

## Phase 3 — 진단 탭 + 서술 생성 (2~3일)

- 포트폴리오 레벨 지표. 핵심은 **위험 배당 노출도** — "10종목 중 2개가 위험"이 아니라
  "내 월배당의 32%가 위험 종목에서 나온다". 이게 실제로 계획을 깨는 숫자다
- 섹터 집중도(HHI), 안전성 가중평균, 커버리지 공백
- 규칙 기반 액션 후보 3종 (축소 검토 / 확대 검토 / 신규 편입 검토)
- 검증 게이트를 거친 AI 서술. **개인화 계층은 순수 코드라 사용자별 AI 호출 0회**

> **이 시점의 제품:** 완성. "늘릴지 줄일지 갈아탈지"에 근거와 함께 답한다.

## 지키기로 한 것

- **표현은 "검토 대상"으로 통일한다.** "사라/팔아라"는 개인화된 투자자문이고,
  "FCF 배당성향이 섹터 경고선을 넘겼다"는 정보 제공이다. 근거 지표를 항상 함께 노출하고,
  데이터 출처·기준일·면책을 하단에 고정한다. 규제 회피용 장식이 아니라 —
  사용자가 판단 근거를 직접 볼 수 있어야 도구가 신뢰를 얻는다.
- **`as_of`를 항상 노출한다.** 마지막 성공이 3일 이상 낡으면 UI에 경고 배너.
- **커버리지 밖 종목은 "미분석"으로 명시한다.** 조용히 빼면 노출도 계산이 틀린다.
- **초기 가중치(40/25/20/15)는 가설이지 정답이 아니다.** 이력 없이는 튜닝할 수 없어서
  Phase 1이 이력 축적부터 시작한다. 검증은 이미 배당을 삭감한 종목(카탈로그에서 빠진
  `LEG`, `TDS`)의 삭감 직전 데이터로 점수를 내 경고가 떴는지 보는 것.
